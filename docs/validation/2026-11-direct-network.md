## D02–D04 记录口径

`probes/06-direct-network/run.ps1` 是可行性探针。它复用探索版 TLS 网关和客户端，使用单独的部署目录与应用入口，往返测试数据只含进程号和递增序号。各项需要分别记录无线调试关闭、USB 拔线和 WLAN 恢复后的证据。

### 无线引导与 Android TLS

- 通过无线 ADB 目标 `10.222.134.72:43411` 上传并校验探针 jar。真机上的跨进程锁测试验证了旧实例清理保留新 owner，持锁期间第二发布进程不能修改 owner，结束持锁进程后第二进程可以完成发布。探针目录为 0700，jar、配置、日志、owner 和稳定锁文件均为 0600。
- Android 进程 PID 为 `25723`，父 PID 为 1，stdin 指向 `/dev/null`，stdout/stderr 都指向本实例日志。设备端读入配置后删除了配置文件。日志记录错误 pin 与错误 token 各自被拒绝，随后固定证书的 TLS 1.2 连接从 `10.222.134.72:36834` 到达有线 PC 的 `10.222.38.129:5272`。首个往返为 15:44:05.964（UTC+8）。USB 目标在此前查询中没有 reverse 规则。
- 以上验证已启动 shell 退出后，探针可以通过局域网和真实 Android TLS 进行通信。无线调试关闭、物理拔线及 WLAN 恢复还需要分别记录。

### D03 证书资源

- 默认 PFX 重导入成功握手。通过证书的实际 CNG 私钥标识检查了容器，正常退出删除容器，强制结束试验进程后容器仍在。使用该试验自己的确切标识删除了遗留容器，并确认消失。
- 在临时副本中改用 `EphemeralKeySet` 后，原有本机跨语言用例在第一个 Java TLS 握手时收到 EOF。详见 [Microsoft 的 Schannel 说明](https://github.com/dotnet/runtime/issues/103101)。正式网关仍需通过异常退出资源检查。
- 另一个临时副本用预先指定名称的 CNG RSA 私钥创建证书，跳过 PFX 重导入，原有本机跨语言套件退出 0。证书创建后注入构造异常，私钥随异常清理。正常退出也能清理。强制结束进程仍会遗留试验容器，但随后可以按创建前已知的名称精确恢复并删除。此试验验证了回收路径，正式代码仍需落实跨进程归属及启动回收。
