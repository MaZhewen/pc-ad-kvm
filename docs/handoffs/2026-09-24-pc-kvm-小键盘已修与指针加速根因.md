## 三、关键决策

- **①** 修法 = 实现 `MSG_ENTER`（相对位移，前提是"PC 侧发 ENTER 前**总是**先发 HOME"这一不变量成立），而非把模型改成"设备永远从左上角开始"。
- **③** 修法 = **设备侧**把小键盘数字改映**数字行** usage；**不**给虚拟键盘加 LED Output 报告（后者要改描述符、且仍依赖手机自身 NumLock 状态）。
- 构建管线：`dist\pckvm.jar` 是唯一部署源；`build-injector.ps1` 负责刷新它，`build-agent.ps1` 只做守卫，**守卫必须在编译之前**（否则守卫触发时会留下一对"新 exe + 旧 jar"）。
- **①② 的待定修法**：把补偿放进**注入器** —— 按固定 3 ms 节拍分批投递，并按 Android 那条加速曲线**反解每一批该发多少**，使设备光标实际位移**恰好等于** PC 发来的增量。这样 PC 侧 1:1 累加模型重新成立 → ② 根治、① 的落点变精确。**尚未实现。**

1. **BOM 陷阱**：Write/Edit 可能丢 BOM → 每轮改完 `.ps1`/`.cs` 用 `head -c 3 F | xxd -p` 与 `git show HEAD:F | head -c 3 | xxd -p` 比对（本次 9/9 一致）。
2. **行数口径**：一律 `wc -l`；本次 `Measure-Object -Line` 报 325，真值 **359**。
3. **git bash 路径改写**：`adb push dist/x /data/local/tmp/x` 会被 MSYS 改写成 Windows 路径 → 该命令前加 `MSYS_NO_PATHCONV=1`；但**全局导出**它会让 `rg /tmp/x` 失败（MSYS 的 `/tmp` ≠ Windows 的 `/tmp`）→ 只在单条命令前加。
4. **不要从 git bash 跑 `pwsh`**（输出乱码，读不出 PASS/FAIL）。
5. **诊断仪器会说谎（本次三例）**：文件 mtime（方案 1）、`GetAsyncKeyState` 低位（方案 2）、`dumpsys input` 的 `Pointer location` 覆盖层（**它对鼠标恒显示 0/0，只有触摸才更新**）。每一个都差点导出错误结论 —— **每条"仪器读数"都要用一个独立通道交叉验证**。
6. **`wait` + 长驻 `adb shell` 会挂死**：一律 `timeout N adb …`；注入器退出路径本身也会挂（`dev.close()`），别依赖它自然退出。
