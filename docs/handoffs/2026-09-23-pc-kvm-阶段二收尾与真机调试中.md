## §三 关键决策

| 决策 | 理由 |
|---|---|
| 显示几何改为**运行时读取 + 每 2 秒轮询旋转** | 实测推翻"几何是常量"的 YAGNI：横竖屏逻辑尺寸不同，硬编码必然错 |
| `_edgeX` 约定 = **触发侧最外侧有效像素列的 x**（右 3839 / 左 0） | 虚拟桌面 x∈[0,3839]，`>= 3840` 永不成立（实测 `SetCursorPos(3840/3841)` 都回落到 3839）。此约定让左右两侧判定写法对称 |
| `OnTakeoverMove` 用**原始增量**判回程方向，不用钳制后的增量 | 进接管时模型落在 x=0，`NextDx(负值)` 恒返回 0 → 用钳制值会让"跨进去再推回"永远触发不了 |
| Task 7/8 的安全网：**未连接绝不夺取前台**、心跳安全网置于早返回**之前** | 掉线后用户再推边缘会夺取前台 + 锁光标，而心跳在 `!IsConnected` 时短路，无人能救 |
| 两处 abort 路径（逃逸键/心跳超时）**必须补发 `MSG_LEAVE`** | 否则手机侧 `buttonsDown` 残留"按住的键" |
| 滚轮/鼠标键转发**门控在 TAKEOVER**（原为无条件） | IDLE 态每次点击/滚轮都被转发到手机 → 用户无法"正常用 PC 而不影响手机" |
| `Program.cs` 红线 250→320→**360** | 320 那步基于**错误测量口径**（见 §六），按 `wc -l` 实测重算 |

## §五 当前状态 ⭐ **正在真机调试一个未解决的缺陷**

**app 已停、设备侧已清场（无注入器、无 `adb reverse`），新会话从干净状态开始。**

**缺陷现象**（用户原话见 §零-5）：Task 9 真机验收时，**接管期在 PC 上打的字出现在 PC 上而不是手机上**；用户并报「鼠标点击或者滑动等情况，非常容易鼠标就回到 PC 中了」。

**已查明的机械事实**（本次会话日志，行 9383 起）：

```
ENTER takeover ×11    LEAVE takeover ×5    前台被抢走 ×6
每次进入接管只存活 0–6 秒（用 PONG 秒序号量）
```
→ 所以"打字进了 PC"是**后果而非病因**：接管被踢出后回到 IDLE，此后按键自然归 PC。**Task 9 的键盘转发本身尚未被有效验证**。

**两个候选机制（需用户两条观测即可判定，我已问但用户未答就发起了交接）**：

- **A — 点击导致前台被抢**：进接管时鼠标被钳在**进入前的那个像素**（屏幕最右侧），而该像素下面是别的窗口 → 一点击，Windows 把点击送给那个窗口并激活它 → 我们丢前台 → 守卫按设计解除抑制。
  *可能的修法*：`Engage()` 把光标钳到**我们自己状态栏窗口内部**（它是 TopMost），这样点击落回我们窗口、前台不变（副作用：PC 光标跳到状态栏上，其实是不错的 UX）。
- **B — 左向抖动导致 LEAVE**：进接管时虚拟光标就在手机左边缘（x=0），此时**任何 `rawDx < 0`（哪怕 -1，点击/滚动常带 -1~-3 抖动）**都满足"在边缘且向外推" → 直接 LEAVE。
  *可能的修法*：要求**累积**的外推量超过阈值（如 ≥8 mickeys，方向反转则清零），而不是看单次增量符号。

**我请用户做的两个判定观测**（10 秒，零风险；新会话可直接让他做）：
1. 进接管后**什么都不碰**，数 5 秒 → 自己退回 PC 吗？
2. 再进接管，**只点击一下左键**（不移动）→ 立刻回 PC 吗？
   判定：①稳 + ②立刻回 = 机制 A；①自己就退 = 另有外部原因；**一动就退** = 机制 B。

## §六 错误与修正 ⭐

| 错误 | 正确做法 |
|---|---|
| 用 Git Bash 发 `adb shell "CLASSPATH=... app_process / Injector"` 一律 `Aborted`，据此怀疑产品启动方式失效 | **MSYS 会改写 `/` 开头参数**：`echo "-Djava.class.path=/x / Injector"` 回显成 `-Djava.class.path=X:/ C:/Users/.../Git/ Injector`。产品走 .NET `ProcessStartInfo`，**不经过 MSYS**。跑 `dist\pc-kvm.exe` 即可证伪（日志有 `# 设备已连接` + `# PONG`）。**bash 下含 `/路径` 的 adb 参数一律不可信** |
| 用 PowerShell `Measure-Object -Line` 量 `Program.cs` 得 225，据此定红线 | 该文件是 **CRLF + BOM**，该口径不可靠；`wc -l` 才是权威（实测 250）。**此错让两个实现者也先后报错行数** |
| 离线 harness 喂 `cursorX=3840` 当"在边缘" | 那是**真实光标物理上达不到**的坐标（虚拟桌面最大 3839）→ 用例掩盖了"TAKEOVER 永远进不去"这个真缺陷。**离线用例的输入必须来自外部约束，不能来自实现者的心智模型** |
