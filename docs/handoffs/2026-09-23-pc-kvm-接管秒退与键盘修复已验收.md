## §三 关键决策

| 决策 | 理由 |
|---|---|
| 钳制区 = **我们自己的窗口**（而非光标所在像素） | 点击送给**光标下**的窗口并激活它。旧写法钳在 (3839,y)（属于别的窗口），**每一次点击都会夺走我们的前台** → 250ms 守卫强制解锁 |
| 再收成**本窗口中心的那一个像素** | 整个窗口矩形会让光标在状态条里滑动（用户实测到并提问）。1×1 既冻住光标，又保证点击落回自己窗口 |
| 回程改为**累积外推 ≥ 40 mickeys** | 入屏瞬间虚拟光标恰在 x=0（与 PC 相邻那条边），旧实现下**任何一次 `rawDx=-1` 抖动都立刻回程** |
| `_lastVx` 区分"走到边界"与"越过边界" | 大扫帚式左滑把光标一次扫到 0 不应算回程意图（否则"滑动就回 PC"） |
| 光标隐藏挂 `Engage`/`Release` 回调，不逐个补调用点 | 七条释放路径全部经过这一对入口 → 自动覆盖，且 `Program.cs` 只 +1 行 |
| **拒绝全局 `ShowCursor(false)`** | 它是桌面级显示计数器，app 被硬杀时不自动恢复——而 `taskkill /F /IM pc-kvm.exe` 正是本项目写明的应急退路。改用"本窗口局部透明光标"，光标离开窗口或进程死掉（系统释放裁剪）即自动恢复 |
| "还原光标"放在 `Release()` **最末尾** | 纯 UX，不能插在"解锁光标 → 还原位置 → 还前台"这条安全序列中间（C1 同一教训） |

## §六 错误与修正 ⭐

| 错误 | 正确做法 |
|---|---|
| **把新代码编到临时路径就让用户测**，导致用户白测一轮（报"光标还是能看见"） | **验证必须验用户实际会跑的那一份**（`dist\pc-kvm.exe`），且**要核实它真的换了**——用 ASCII 扫二进制找新导入符号（`CreateCursor` / `SetCursorHidden`），比看时间戳可靠 |
| 让用户"退出 app 后告诉我，我再编" | **协调会漏**。正确做法：挂一个后台任务**等进程消失就自动构建并回报**，让用户只需退出、无需通知 |
| `CheckForeground` 里 `_log` 排在 `Release()` 之前（且我恰在这行前又加了 `TitleOf` —— 跨进程同步 `SendMessage`） | 日志抛异常或目标窗口挂死 → **光标留在钳住状态、守卫定时器随后也失效**。顺序必须是 **`Release()` → `ForegroundLost` → 最后才取证写日志** |
| `EdgeTracker` 里 `outward <= 0` 清零 | `dx=0` 的纯纵向事件（日志里大量存在）会反复清零累积量 → 斜推时**"回不去"**。改为 `outward == 0` 既不累积也不清零 |
| `Engage()` 两条新守卫在 `SetForegroundWindow` **之后** `return false` | 调用方只 `AbortTakeover()` 不 `Release()` → 前台被扣在状态条上。加 `GiveBackForeground()`；且 `GetLastWin32Error()` 必须**先取到局部变量**（`SetForegroundWindow` 会覆盖 last-error） |
| `DllImport` 缺 `SetLastError = true` | `Marshal.GetLastWin32Error()` 读到的是**上一次别的调用**留下的值 → `err=` 日志全是垃圾。本项目已多次栽在"诊断仪器说谎"上 |
| `adb devices` 空（当晚第 2 次掉线） | `adb kill-server` **不够**：要先 `taskkill /F /IM adb.exe` 强杀所有 adb 进程，再 `adb start-server`（实测恢复） |
| `dist\pckvm.jar` 是旧的（5683）而 `%TEMP%` 是新的（5916） | app 启动时推的是 **`dist` 那份**，会把手工推的新 jar 覆盖掉。改完设备侧必须同步 `dist\pckvm.jar` |
