## §一 核心目标

让 Windows PC 的键鼠**无缝跨越**到 Android 手机上操作（Synergy 式软件 KVM）：鼠标推到显示器外侧边缘 → 控制权移交手机、手机出现真光标 → 推回边缘收回。**不传画面**，用户看手机自己的屏。

## §三 关键决策

| 决策 | 理由 |
|---|---|
| PC 端持有虚拟光标模型 | 边缘判定与入屏逻辑聚在一处，保持单一状态机；手机侧保持"哑执行器" |
| 抑制用**焦点小窗**而非全局钩子 | 青骓会把键盘钩子当键盘记录器。实测证明焦点方案零泄漏 |
| **必须**用 `AttachThreadInput` 绕行 | 朴素 `SetForegroundWindow` 从后台进程实测抢不到前台 |
| 去程用比例映射、接管期用 1:1 | PC 边缘高 1080 vs 手机屏高 3200，全程比例映射会让鼠标快约 3 倍 |
| 进入接管前**必须推角落归零** | UHID 光标位置跨设备销毁/重建**持续存在**（实测），不归零则模型与真光标永久错位 |
| 手机侧走 `adb push`+`app_process` | 实测可行 → 真正的零安装 |
| 传输走 `adb reverse` 隧道 | 完全不碰办公网（有线 PC ↔ 无线手机大概率被 AP 隔离） |

## §六 错误与修正 ⭐

| 错误 | 正确做法 |
|---|---|
| `RAWMOUSE` 用朴素 `LayoutKind.Sequential` | C 里 `ulButtons` 是与匿名结构体的联合，`usFlags` 后有 2 字节填充。**必须显式补 `_pad`**，否则 `usButtonFlags` 落偏移 2 而非 4，之后全字段错位、数据全垃圾但**不报错** |
| csc 用 `/nologo` 等 `/` 前缀开关 | Git Bash 的 MSYS 路径转换会吃成 `C:/.../Git/nologo`，报误导性的 `CS2001 未能找到源文件`。**一律用 `-` 前缀** |
| `.ps1` 存为无 BOM 的 UTF-8 | PowerShell 5.1 按 GBK 误读中文注释，**静默破坏解析**（变量变 null）。Write 工具产出的是无 BOM，**每次写完必须核首三字节 = `EF BB BF`** |
| 计划 Task 4 的字面照做 | `transport` 声明在处理器之后时编译不过——C# 局部变量不能前向引用。**跨任务计划要查声明顺序，不只是文件与接口** |
| 计划 Task 3 的 `Files:` 块 | 漏列了 3 个实际要建的文件（`StdinMode.java`/`KeyState.java`/`ScancodeMap.java`）。**Files 块与步骤正文要交叉核对** |
| 计划 Task 7 的 `out uint _` | **那是 C# 7 内联 out 声明**，而本机 csc 只到 C# 5。改为先声明 `uint fgPid;` 再传。**飞行前扫描靠"语言版本 vs 实际写法"对照才扫得出来** |
| `scrcpy --mouse=sdk` 无光标就以为失败 | 它是**探针手段**验证注入路径，不是产品形态。光标要 UHID 才有 |
| 音量狂减以为是自己的探针 | 探针都没跑。真凶 `GameViewer.exe`（`SendInput` 注入）。**判据：Raw Input 里 `hDevice` 为 NULL = 进程注入，非设备**。音量键走 UsagePage `0x0C`，普通键盘探针**看不到** |
| `adb devices` 为空就以为手机没插 | Windows 侧仍可见 `Android ADB Interface`。**3 个 adb server 争抢**。`adb kill-server` + `start-server` |
