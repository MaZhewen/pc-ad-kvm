# Windows ↔ Android 共享剪贴板

日期：2026-10-15。状态：用户已确认设计，功能已实现并构建，真机应用验收进行中。

## 已确认需求

在一侧正常复制，切换到另一侧后直接 Ctrl+V。支持双向纯文本、图片和文件；USB 与无线连接共用同一实现。文本涵盖中文、链接、多行和表情，文件传输为复制语义。

用户已指定应用优先级：**微信优先，其次文件管理器**。以实际安装版本的行为验收，不用其他接收应用的通过结果替代。

沿用当前绿色 Windows 程序与 Android app_process 注入器，优先保持手机端零安装。粘贴能力按接收应用的实际支持验收；不能把传输成功、文件落盘或路径文本当成图片/文件粘贴成功。

## 方案比较

1. **推荐：扩展现有连接，优先验证零安装路径。** 文本通过系统剪贴板接口同步；图片和文件需要实际传输内容，并在 Android 端生成可授权的 content URI。优先验证系统媒体/文档提供器能否满足目标设备上的权限与应用行为。复用当前连接身份校验，新增独立的数据通道避免大文件阻塞键鼠。兼容性必须通过真机探测，不能预先承诺所有文件管理器。
2. **独立 Android 辅助 APK。** 提供受控缓存和 ContentProvider，图片/文件来源可控，但改变原有手机零安装约束；仍不能使本身不支持粘贴的应用支持 Ctrl+V。只有零安装路径验证失败、并获得用户同意后才采用。
3. **文件先传到下载目录，再手动选择附件。** 能实现文件传输，但操作体验不符合直接 Ctrl+V，仅可作为明确标注的降级，不能作为本需求完成标准。

## 行为与内容映射

Windows 读取 Unicode 文本、位图/PNG 与文件列表；Android 读取标准 ClipData 的文本与 content URI。Android 应用只在私有文件管理器状态中保存“复制”动作、未发布系统 ClipData 时，无法直接视为共享剪贴板事件。

文本保持原文。图片保持可解码的图像内容，向 Windows 发布图片格式，向 Android 发布匹配 MIME 的可读 URI。文件保留原文件名与内容，支持多文件；目录递归复制、剪切删除和剪贴板历史不属于首版。

图片或文件复制后后台传输，完成后一次性发布目标剪贴板。传输中显示进度；失败保留目标原剪贴板并说明原因。尚未就绪时明确显示“正在同步”，避免把旧内容误报为本次同步结果。不能仅注入按键或把文件路径作为文本发送来替代真实内容。

## 模块与接入

- Windows 剪贴板适配器：利用已有 STA 消息循环监听变化，读取/写入剪贴板；处理句柄重建、占用重试与退出解绑。剪贴板调用不在网络线程执行。
- Android 剪贴板适配器：封装系统接口差异、变更通知、URI 内容读取与目标 URI 发布；按当前用户、默认显示环境和 shell 身份访问。不修改系统全局权限，不提权。
- 同步协调器：管理会话代际、更新标识、内容描述和同步状态，抑制自身写入产生的回声；不通过文本内容日志实现排查。
- 内容传输器：分块流式传输，限制在途数据与缓存占用；校验长度、内容摘要、文件名及目标路径，完成后原子提交。只操作本功能创建的临时文件，清理不删除用户保存的副本。
- 数据通道：通过 ADB reverse 建立与当前认证会话绑定的通道；不开放局域网监听。大文件不占用现有输入队列，心跳、按键释放和紧急退出保持及时。
- 状态展示：在现有连接窗口/托盘提供开关、同步中、完成与失败状态，不弹出独立常驻传输窗口。

## 同步顺序与生命周期

仅在已选目标的认证会话内同步。新连接先记录两端快照，不立即用某端历史内容覆盖另一端；首个新的复制事件决定更新。首次跨屏时按源端当前内容触发同步，支持连接前已复制内容。

每次复制生成独立更新标识；协调器按接收次序处理并使较新的更新取代旧任务。异步传输结果发布前再次检查标识、会话代际和目标剪贴板是否已被本地修改，防止旧传输覆盖新复制。回声识别同时考虑更新来源与实际发布结果；同内容重复制不能形成无限回传。

断开、切换设备、关闭共享功能或退出时停止任务、释放监听并清理未完成文件；迟到回调不能写入新设备会话。已完成且仍被当前剪贴板引用的缓存需保持可读，替换后再按保留策略清理；不能刚发布 URI/文件列表就删除底层文件。

## 错误与边界

读取权限被拒绝、URI 已失效、接收应用不支持目标格式、空间不足、文件过大、源文件消失、传输中断分别报告。诊断只记录类型、字节数、阶段和错误类别，不记录剪贴板正文或文件内容。

输入链路与剪贴板故障隔离；某种格式不可用不能使鼠标键盘失效。发布不完整数据、把权限失败当空文本清空另一端、未验证就声称应用支持图片/文件粘贴，均不允许。

## 验证与完成标准

先在目标设备上验证：shell 能否监听并读写文本、读取复制产生的 URI、为收到的图片/文件取得可授权 URI，以及接收应用是否实际消费这些 URI。该阶段决定能否继续零安装实现。若失败，记录具体失败接口与应用场景，再请用户决定是否接受辅助 APK。

离线测试覆盖文本编码、图片转换、文件元信息、分块重组/校验、恶意文件名、截断/超限、回声抑制、并发更新、过期传输、断线/重连和缓存寿命。运行现有 transport、session、键盘、连接及切屏相关回归，并构建同批 exe/jar。

真机验收覆盖 USB 与无线双向：中文多行文本复制粘贴、截图到聊天输入框、文件列表到支持粘贴的接收端、多文件、复制后立即切屏粘贴、传输中复制新内容、传输中断开，以及大文件传输期间鼠标/键盘响应。

### 目标应用验收矩阵

| 优先级 | 场景 | 通过标准 |
| --- | --- | --- |
| P0 | Windows 复制中文多行文本 → Android 微信输入框 Ctrl+V | 文本正确且保持换行；不自动发送消息 |
| P0 | Android 微信复制消息文本 → Windows 输入框 Ctrl+V | 获得当前复制文本，无回声覆盖 |
| P0 | Windows 复制截图/图片 → Android 微信输入框 Ctrl+V | 微信接受真实图片，进入预览或待发送状态；不自动确认或发送 |
| P0 | Windows 资源管理器复制文件 → Android 微信 Ctrl+V | 微信接受可读取的真实文件，进入附件或待发送状态；落盘或路径文本不算通过 |
| P0 | Android 微信执行可用的图片/文件复制动作 → Windows 粘贴 | 若应用发布系统 ClipData，图片或文件内容可用；若仅提供保存/转发且无系统复制动作，记录为源应用能力边界 |
| P1 | Windows 复制一个/多个文件 → Android 文件管理器 Ctrl+V | 支持粘贴的目标目录出现内容一致的文件，原文件保留 |
| P1 | Android 文件管理器复制一个/多个文件 → Windows 资源管理器 Ctrl+V | 文件名和内容一致，原文件保留 |

先识别当前文件管理器的包名与版本，再验证它是否使用标准 ClipData，或只维护内部复制状态。若微信或文件管理器没有对应的粘贴入口，报告具体不支持的方向和类型，再评估适配方式；不能默认为所有 Android 应用提供通用文件 Ctrl+V。

真机验证不自动点击微信发送按钮。测试数据使用明确标记的无敏感测试内容，不向联系人或群组发送消息。

## 实现与验证记录（2026-10-15）

- 功能分支 `codex/shared-clipboard` 从本地 master `93ce77a` 创建，保留既有无线、光标与双击修复；独立试用产物位于 `G:\pc-kvm\dist\shared-clipboard`。
- Android 16 / 主用户，微信 8.0.79、小米文件管理器 8.2.3.2。无线端口变化后重新核验设备身份；本次真机使用无线连接，未另外重跑 USB 和其他用户配置。
- 最新源码的真实双向链路通过：中文多行文本、PNG 图片、文件字节及摘要。测试使用正式服务、协议与平台适配器，结束后恢复双方原剪贴板，不发送消息。
- 微信文件传输助手：用正式 UHID 键盘路径注入 Ctrl+V，中文多行文本正确；640×360 标记图片进入图片预览，31 字节标记文件进入附件预览。图片和文件均返回取消，测试文字已清除，未点击发送。
- 小米文件管理器：「复制到剪贴板」发布标准 content URI，正式 Android 适配器读取自建 source-test.txt 的字节摘要一致；普通内部「复制」不能等同于系统复制。目录界面对外部 MediaStore 文件及其自身发布的文件 Ctrl+V 均无粘贴结果，专用目标目录保持空。该版本暂不支持作为文件 Ctrl+V 目标，不以落盘代替成功。
- Android 微信的图片/文件通常使用保存或转发入口；本次未验证其向系统剪贴板发布二进制内容的动作。反向图片/文件链路已用标准 ClipData 验证，不能因此声称微信具备对应复制入口。
- 修复真机发现的二进制快照标识缺失，并新增先失败后通过的回归。修复连接后的同内容重复制被本地基线误去重：本地基线不再当成已同步内容，C#/Java 均有 RED→GREEN 回归。
- 最终完整剪贴板回归通过：编码 C#/Java 各 64 项及双向交叉样本；Android 会话 104 项、适配器 30 项；Windows 服务 174 项、原生剪贴板 23 项；额外覆盖 URI 路由、缓存所有权/引用/年龄/容量和配置接入。
- 既有 transport、session、agent-logic、coordinator、connection、connection-form、edge-tracker、absolute-pointer、double-click、wifi-latency、native-cursor、drag-cursor、scancode-map、single-instance 回归通过。解锁后 message-host 的点击及设置回归通过；无交互前台窗口时的 foreground takeover 子项被测试工具跳过，不计为通过。
- 已审查并修复延迟本地回调覆盖新内容、失败接收缓存清理、成功文本/图片缓存清理；已发布文件和 URI 保持可读，自有旧缓存按引用保护及 24 小时 / 2 GiB 策略回收。
- 同批 exe/jar 构建成功。大文件与输入通道分离；截断、取消、超限、断线及并发覆盖有自动化测试。多文件和大型文件传输期间操作体验仍需用户实际场景验证，不声称已完成全部性能矩阵。
- 证据保留在工作区忽略的 `dist/regression-results` 与 `dist/clipboard-device-test`，含应用截图；截图包含当前界面，因此不提交源码。自建文件管理器测试目录已移除，原剪贴板已恢复。
