# Android 指针坐标与平滑度修复方案（待确认）

## 目标与已知证据
保持现有 ADB + app_process、手机无 APK 的使用方式，解决提前回 PC、入屏落点偏移及移动不平滑。手机只读查询为 Android 16 / API 36。
PC CursorModel 累加发送增量，而 UHID 相对鼠标经过 Android 指针处理；既有真机记录显示 dx=1000 实际约移动 2876 像素。当前日志的退出由模型边缘判定触发。
PointerPlan 对两轴独立填满 127：例如 (254,127) 被拆为 (127,127)+(127,0)，改变直线路径。网络读线程同步写入全部 UHID 报告，无独立节拍。轨迹缺陷确定；投递抖动对体感的贡献需测量。

## 方案比较
1. 推荐：先验证免安装绝对鼠标坐标路径，成功后采用绝对目标坐标和有界投递队列。避免依赖 Android 相对鼠标加速曲线。
2. 关闭相对鼠标加速：仅在 shell 权限下存在可用接口且不影响其他设备时考虑。系统内部方法存在不代表 app_process 可以调用。
3. 加速曲线反解：依赖设备、事件历史及真实投递时间，不作为根治方案；调大退出阈值同样不满足目标。

## 实施边界与验证门槛
首先制作独立、可退出的真机探针，验证候选绝对输入是否保持真实鼠标光标、悬停、左右键、拖动和滚轮语义。不能仅把 HID Rel 改成 Abs 就宣布成功，也不能用触屏点击替代鼠标悬停。若设备不支持，停止该路径并报告限制，不能静默退回漂移方案。
键盘保持现有已验证的 UHID 路径。

## 成功路径的设计
PC 保留浮点/余数累计的目标坐标，传送带序号和几何版本的绝对位置；Android 以统一坐标执行鼠标输入。进入手机直接定位，取消依赖 HOME 大量相对报告的定位方式。
回程与当前几何版本、设备已执行的位置确认关联，避免尚未执行的位置触发回 PC；旋转、重连清除旧队列和旧确认。执行确认与实际屏幕落点必须在真机验证，不能把提交成功等同于已显示。
移动采用独立发送线程及有界队列，初始评估 4–8ms 投递间隔；用测得的时延调整，不固定承诺某个频率。连续移动可合并最新目标，按钮/滚轮/按键为顺序屏障，点击前必须先应用其对应位置。停止移动后不得持续补跑旧轨迹。
记录采集、排队、发送、执行时间，分辨 PC UI 阻塞、网络抖动及 Android 投递延迟。避免逐移动事件刷盘。

## 验收
- 左/右挂接 × 横/竖屏 × 灵敏度 0.10、0.50、3.00。
- 指定角点、中心、往返路径，真机测量误差，目标不超过 2 像素；达不到则不能宣称坐标问题已根治。
- 鼠标未到邻接边缘不回 PC；到边缘继续外推正常返回。
- 慢移、快移、斜线、圆形、点击、拖动、滚轮；统计事件延迟分布与队列长度，确认不持续积压。
- 断连、旋转、退出释放按钮与修饰键，不执行旧移动。
