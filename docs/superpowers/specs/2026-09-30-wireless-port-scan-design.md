# 单设备无线调试端口扫描设计

状态：已按用户确认的方案定稿；仅针对用户输入的 IPv4 地址手动扫描。

## 目标与边界

Android 11+ 无线调试连接端口随机分配，当前网络中 `adb mdns services` 未返回服务。连接窗口增加「扫描端口」，使用户输入 `10.222.240.129` 这类 IPv4 地址即可寻找连接端口。扫描仅在用户点击后执行，只访问该 IP 的 TCP 端口 1–65535；不扫描网段、不猜配对码、不自动部署 KVM。现有配对与手动 `IPv4:端口` 输入仍可使用。

## 数据流

1. 连接窗口校验输入为 IPv4（也接受现有 `IPv4:端口` 文本并提取 IP）。先读取 ADB mDNS 的连接服务；若有该 IP 的候选端口，先验证候选。
2. 没有可用候选时，用有限并发 TCP 连接探测该 IP 的端口。优先扫描常见动态端口区间，再扫其余端口；每个端口有短超时，整体有上限。进度和取消按钮始终可用，关闭窗口会取消扫描。
3. TCP 开放仅表示候选。对候选执行 `adb connect IPv4:端口`，随后在 `adb devices -l` 中确认该精确端点为 `device`，再读非空且非 `unknown` 的 `ro.serialno`。若已有绑定身份，必须相等。验证失败的候选不能填入连接地址。ADB 传输由本机多个程序共享，扫描无法可靠证明连接所有权，因此不执行 `adb disconnect`；连接失败留下的 `offline` 记录可由用户按端点手动清理。
4. 第一个通过验证的端点填入连接地址栏，提示用户点击「连接」。扫描本身不改变当前 KVM 会话、保存配置或触发注入器部署。没有结果时说明可能未配对、网络过滤或端口变化，并保留手动输入入口。

## 结构

- `WirelessPortScanner.cs`：单 IP、指定端口序列的有限并发 TCP 探测；提供进度、候选回调和取消；不依赖 ADB 或 UI，便于本地 listener 测试。
- `ConnectionCoordinator.cs`：对 mDNS/TCP 候选执行目标明确的 ADB 在线与身份验证，并清理扫描新建的错误连接。
- `ConnectionForm.cs`：输入、进度、取消和结果填入；不阻塞 WinForms 线程。

默认并发上限 128，单端口 TCP 超时 300 毫秒，整体上限 180 秒；扫描到已验证的 ADB 端点立即停止。完整扫描的时长取决于网络过滤方式，达到上限时报告已扫描数量，不声称覆盖全部端口。

## 验收

- 本地监听端口被发现，关闭端口不作为候选；取消能在短时间内停止。
- 错误 IP/地址文本在启动扫描前拒绝；mDNS 只取同 IP 的连接服务，不把配对服务当连接服务。
- 开放的非 ADB 端口、未授权设备、已绑定身份不匹配均不填入地址，也不启动 KVM。
- 已验证端点填入输入框；关闭窗口或切换连接操作时不让旧扫描结果覆盖新输入。
- 原连接、配对、USB 与离线回归继续通过；exe 与 jar 构建通过。
