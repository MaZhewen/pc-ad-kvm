# 独立网络键鼠共享设计

> 2026-11-11 归档说明：下文保留设计编制时的状态。独立 Wi-Fi 实现已提交于 `4a9f0dc`（`v1.1.0-rc.1`）；实现已提交不等于全部真机验收通过，验证范围见[验证记录](../../validation/2026-11-direct-network.md)。

日期：2026-11-04。作者：Astra。状态：方向已由用户选择，本文供审阅；本轮仅产出文档，未继续实施。本文是本轮正式设计提案；2026-11-03 英文草稿与未集成代码只作为探索记录，冲突时以本文为准。

## 1. 问题与目标

当前无线模式以无线 ADB 和 adb reverse 承载键鼠及剪贴板。用户在平板亮屏操作时也遇到频繁掉线；已有排查指向 Wi-Fi 接入点 BSSID 变化后 Android 关闭无线调试。重新发现 ADB 地址无法解决调试开关已关闭的问题。

本次把 ADB 缩小为部署、授权和启动工具。Android 辅助进程启动后主动连接 PC 的独立 TLS 服务，承载键鼠、剪贴板和显示几何信息。无线调试关闭、ADB 连接消失及 Wi-Fi 短暂漫游，不应直接结束已启动的辅助进程；网络恢复且 PC 地址仍可达时，无需重新打开无线调试即可重连。

硬约束：无 APK、无 Root、无 Shizuku、不传画面；保留 Java 8 app_process 与 /dev/uhid，PC 保留 C# 5。现有 USB 模式保持可选。首次启动既支持已授权无线 ADB，也支持 USB ADB，不强制插线。保留现有 AttachThreadInput 抑制方式、4376 字节 UHID CREATE2、接管前推角落归零，以及用户已有按键状态修复。

本次不实现开机自启、系统服务、跨公网连接、自动修改企业网络策略、PC 地址自动迁移、多设备同时接管。辅助进程被系统杀死或平板重启后仍需要 ADB 再次启动。

## 2. 方案选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| Android 主动连接 PC，独立 TLS 双通道 | Android 地址变化后可重新出站；沿用现有 PC 输入/剪贴板处理 | PC 需允许局域网入站；采用此方案 |
| PC 主动连接 Android 的监听端口 | PC 不需新增局域网监听 | 需处理平板地址发现、监听权限与暴露面；不采用 |
| 继续依赖无线 ADB 自动重连 | 改动少 | 调试开关关闭时无恢复路径；不能满足目标 |

PC 选择路由到目标平板 WLAN 地址所使用的单个 IPv4 接口，仅绑定该具体地址。PC 可以使用有线以太网，平板使用 Wi-Fi，只要双方可达，不要求 PC 也连接 Wi-Fi。TLS 网关转发至原有回环输入端口，以及可选的回环剪贴板端口。直连模式不建立 adb reverse。USB 继续使用既有独立路径，不经过局域网网关。

## 3. 组件与责任

| 组件 | 责任与边界 |
| --- | --- |
| DirectBootstrap | 选定唯一 ADB target；探测 WLAN 与 PC 路由；上传私有部署目录；原子发布 owner；脱离 ADB 启动；只清理自身实例 |
| DirectNetworkGateway | TLS、鉴权、握手限时、sessionId 与通道归属；只有认证后的字节才能进入回环服务；不处理键鼠业务 |
| ConnectionCoordinator | 连接状态、generation、取消及重新启动；决定能否接管；运行期不把 ADB 离线视为 KVM 离线 |
| DirectDaemon / DirectSessionConfig | 外层进程生命周期、owner、截止时间、退避；每次重连创建全新输入会话 |
| PinnedTls | TLS 证书固定、公用握手编码及失败分类 |
| Injector / SessionLink | 现有输入协议、UHID、释放输入、双向心跳和显示几何上报 |
| ClipboardService / ClipboardSession | 独立 TLS 通道、当前 sessionId 归属、失败隔离；禁用剪贴板不能阻塞输入 |
| Watchers / PointerSession | 当前 generation 的心跳和几何有效性；直连不再轮询 ADB 屏幕信息 |

PC 启动网关后生成 host、port、证书摘要、随机 token、instanceId 配置，经已授权 ADB 送达 Android。Android 建立输入通道，收到会话编号后才建立剪贴板通道。数据流为 Android TLS → PC 网关 → PC 回环业务端口，反向同路。

## 4. 生命周期与状态机

PC 状态顺序为：未连接 → 准备启动 → 等待输入认证 → 等待设备就绪 → 已就绪。已就绪表示当前输入会话认证通过、双向心跳有效、几何有效并完成现有 PointerReady/归零准备；不表示自动接管。用户仍按原来的边缘/快捷键操作接管。

进程启动命令退出成功只表示启动请求已发出。TLS 成功只表示加密连接已建立。收到设备几何只说明尺寸已知。界面不得提前显示“可控制”。剪贴板状态单独显示“可用／关闭／暂不可用”，不参与输入就绪判定。

输入 EOF、心跳过期或协议错误：PC 立即退出接管并恢复本机输入，递增 generation、清空待发输入与剪贴板任务；Android 释放全部按键和按钮、关闭会话 UHID 和会话 socket。外层 daemon 保留，进入等待重连。旧 generation 的异步完成事件、几何、PONG 和剪贴板回调一律丢弃。重连不重放按键，不自动恢复接管。

心跳延续现有 2 秒失效门槛，发送间隔 500 毫秒；Android 同样以最后有效 PC 心跳执行失效释放，避免仅依赖 TCP 长时间超时。暂停/唤醒后先判过期再处理输入，不追赶发送旧队列。可调参必须基于真机记录，不能通过延长失效门槛掩盖网络问题。

首次启动最多等待 60 秒到达已就绪。曾到达已就绪后，每次输入会话失效开始计算连续离线 30 分钟；仅完整恢复已就绪才重置此期限，反复 TLS 连接不能无限延寿。重连间隔按 1、2、4、5 秒封顶，加 0–250 毫秒随机抖动，单次网络连接及握手总预算 5 秒，所有等待可取消。达到期限后 daemon 退出，PC 显示“需要重新启动设备连接”。计时使用包含休眠时长的单调时钟；Android 采用 elapsedRealtime 语义。

停止：PC 先撤销本实例接管并拒绝新连接准入，保留当前已认证输入通道的写权限，以最多 1 秒预算发送 STOP；随后撤销 sessionId 并关闭所有连接、listener 和密钥资源。STOP 交付不能保证，UI 不声称远端已退出；ADB 可用时写本实例停止标记，否则 daemon 最迟在离线期限结束后退出。无需为了停止重新连接无线 ADB。

## 5. 启动、替换与部署回滚

每次启动使用随机 instanceId 和独立目录 `/data/local/tmp/pckvm-direct-<instanceId>/`，目录 0700，配置、日志及 owner 相关文件 0600。token 不出现在命令行、诊断日志、异常消息和长期设置中。PC 临时配置采用当前用户私有目录并在上传完成后删除；既有 ADB 授权被视为可信传输边界。

启动顺序：确认目标与路由 → 创建回环输入及可选剪贴板服务 → 创建网关 → 上传 jar/config 至实例目录并设置权限 → 校验文件完整性 → 发布 owner → 用 nohup、setsid、完整重定向 stdin/stdout/stderr 启动 app_process → 等待当前 instanceId 的已就绪。

owner 记录当前 instanceId；更新须在 Android 文件锁保护下通过临时文件原子替换。新实例持锁发布 owner 后，旧实例发现 owner 变化便释放会话退出。每个实例仅检查自己的 stop 文件；旧实例清理只删除自己的目录，绝不执行“先读共享 owner 再无锁删除”。共享 owner 的清理也必须在同一锁内比较当前实例后执行。锁文件保持稳定不删除；崩溃由系统释放文件锁。具体文件锁在目标 app_process 环境的可用性列入首阶段实测。

PC 对同一目标串行化启动操作；取消或超时后，晚到的 ADB 成功回调不得发布新状态。替换新实例失败时关闭新网关、撤销新 token、标记新实例停止、清理本实例文件；不自动恢复旧 owner，避免复活已停止的旧实例。用户可明确重试。若失败发生在 owner 切换之前，旧会话可继续；切换之后旧会话已让位，界面明确“启动失败，需要重试”。

异常退出留下的实例目录在下次 ADB 启动时按 owner 和存活状态安全清理；不按进程名 kill，不使用共享路径通配删除。daemon 常规退出自行清理；无连接时进程崩溃遗留的文件允许暂留，下一次启动处理。

## 6. 协议与会话身份

现有探索使用 DKVM v1，仅 token 与通道号不能阻止同一启动内旧剪贴板迟到混入。本设计采用 DKVM v2，双方打包升级，不兼容探索 v1；版本不符立即关闭并提示版本不匹配，不降级明文。

TLS 建立后客户端发送固定长度头：ASCII `DKVM` 4 字节、version 1 字节（2）、channel 1 字节（输入 1／剪贴板 2）、instanceId 16 字节、token 32 字节、sessionId 16 字节，共 70 字节。instanceId 采用 32 位十六进制字符串逐对解码的网络表示，避免 .NET Guid 内存字节序差异。输入请求 sessionId 全零；剪贴板必须为已获准输入的随机 16 字节 sessionId。

服务端先读取并校验前 6 字节，再读取 v2 剩余的 64 字节；旧版或非法版本立即返回格式错误并关闭，不等待旧客户端永远不会发送的 v2 尾部。两段读取共用同一个握手截止时间。

服务端响应 17 字节：status 1 字节（0 成功、1 版本或格式错误、2 鉴权失败、3 已有通道、4 会话过期、5 通道不可用），后接 sessionId 16 字节；失败时全零并关闭。状态仅在 TLS 内发送，不回显 token。输入成功时 PC 用密码学随机数创建 sessionId，并绑定本地 generation。输入会话仍活跃时拒绝重复输入，不踢掉健康旧会话。旧会话被失效清理完成后才接受新输入。剪贴板必须匹配当前 instanceId、token、sessionId 且输入会话仍有效，重复剪贴板同样拒绝。

sessionId 是网络会话身份，generation 是 PC 内部异步工作身份，不能相互替代。输入断开时网关原子撤销 sessionId 并关闭对应剪贴板；已经排队的旧回调由 generation 二次过滤。握手最多保留 4 个未完成连接，超过直接关闭；从 accept 起 5 秒总截止覆盖 TLS 和应用鉴权，避免慢客户端占位。鉴权失败不得建立回环连接。

鉴权之后沿用原有定长输入帧与剪贴板协议。新增设备→PC `0x10`，负载 5 字节：uint16 宽、uint16 高（小端）、uint8 rotation（0–3）；宽高必须大于 0，与现有逻辑显示坐标一致。首次连接及变化时立即发送；设备端每 500 毫秒检查一次几何，无法读取时不得伪造 ready。PC 将几何映射到当前 generation 和现有 geometry epoch，旋转期间释放旧输入、暂停发送并重新协商，旧 epoch 指针确认无效；若同一网络会话仍健康且用户原本处于接管中，完成新几何准备后恢复原接管状态。仅网络断线或会话更换要求用户再次主动接管，不能把旋转误当断线。新增 PC→设备 `0x11`，零负载 STOP，仅直连已认证输入会话允许。新增 PC→设备 `0x12` SESSION_READY，负载为当前 geometry epoch 的 uint32 小端，共 4 字节。PC 收到该 epoch 的既有 PointerReady 且心跳有效后发送 SESSION_READY；写出成功才将本地状态设为已就绪。Android 仅在本次输入会话收到匹配已发 PointerReady 的 epoch 后，通知 daemon 完整已就绪并刷新期限；旧 epoch 或未准备时的确认无效。旋转后按新 epoch 再次确认，不能重置网络会话身份。未知帧、错误方向或非法负载结束本次会话。

## 7. 安全及运行环境

TLS 1.2 为最低版本，Android 固定启动配置中的服务端证书 SHA-256 摘要；指纹精确匹配为自签证书的信任依据，仍执行 TLS 密钥持有证明，不接受任意证书或静默回退。PC 使用每次启动新生成的 256 位 token 验证设备，恒定时间比较；实例结束即撤销。设备身份来自用户选定并经 ADB 授权的目标与私密配置，不把来源 IP 或设备名称当作认证。该设计不抵御已取得本机用户或 Android shell 权限的攻击者。

独立模式最低 .NET Framework 4.8，继续用 C# 5 编译；启动前检查并给出明确错误。证书在内存创建，不安装至系统信任库。探索中的 PFX 重导入与 Schannel 私钥容器须验证正常退出、构造失败和异常退出的资源行为；不允许无限积累持久私钥。Java 源代码保持 Java 8，目标 Android 16 的实际 TLS 支持必须真机验证。

网关绑定单个明确 IPv4，不监听 0.0.0.0。防火墙允许规则建议限定当前程序、选定本地地址、私有网络与本地子网；不自动放宽公共网络或企业安全策略。企业 AP 客户端隔离、跨 VLAN 不通、入站被策略阻止时，本方案不可用；界面说明是局域网连通失败，不建议反复配对。动态端口使用程序级允许规则，不长期开放固定端口。禁用或初始化失败的剪贴板不创建该转发目标，channel 2 返回不可用。

## 8. 故障与用户体验

| 场景 | 预期行为 |
| --- | --- |
| 首次用无线 ADB | 配对/连接后部署；显示启动进度；成功后提示 ADB 已不参与日常通信 |
| USB ADB 启动独立 Wi-Fi | 使用 USB 选定目标，仍检查 WLAN 路由；启动后可拔线；不混淆为 USB 传输模式 |
| 无线调试关闭／ADB 离线 | 已就绪会话保持，不执行部署和几何 shell 轮询 |
| AP 漫游、平板 IP 改变 | 若 daemon 存活且 PC 原地址仍可达，则自动重连；安全回到本机输入 |
| PC 休眠后唤醒 | 废弃旧会话；原 listener 与地址仍有效且 daemon 未超过连续离线 30 分钟时等待设备重连，否则需 ADB 重新启动 |
| PC IP 或接口改变 | 原配置失效，提示通过 ADB 重新启动；本次不做地址发现协议 |
| PC 应用／平板重启，daemon 被杀 | 需要 ADB 重新启动；无线调试关闭时用户重新打开，也可用 USB |
| 剪贴板异常 | 输入继续；仅重建当前 sessionId 的剪贴板连接，不重放旧传输 |
| 网络中断超过 30 分钟 | daemon 退出；再次使用需 ADB 启动 |

配置兼容原有 WirelessTls 保存值，将其解释为独立 Wi-Fi 启动入口；不静默改成 USB，不恢复旧 reverse 数据通道。USB 引导也必须匹配用户已绑定或明确选择的同一设备身份，不能选列表首台。普通掉线状态为“等待重新连接”，另提供明确的“重新启动连接”动作，后者才调用 ADB 并替换实例。错误区分 ADB 授权、上传、进程启动、TLS 认证、网络可达、几何准备和运行期断线。日志记录阶段、instanceId 的非秘密短标识、generation、断线原因和时间，不记录剪贴板内容或凭据。

## 9. 验收与证据边界

首个门槛必须在目标 Android 16 小米 25053RP5CC 上验证：无线 ADB 启动后关闭无线调试，进程继续存在且独立加密测试连接仍可用；随后在 ADB 关闭期间主动断开并恢复 WLAN，直接连接恢复。USB 启动后拔线也需独立验证。setsid/nohup 命令存在不等于进程真正脱离 adbd；若门槛失败，应先解决生命周期或重新评估零 APK 约束，不进入 UI 大规模集成。

阶段 D02–D04 使用独立心跳和测试数据验证上述存活、加密连通及重连前提，不要求提前完成正式键鼠集成；关闭 ADB 后真实键鼠和剪贴板持续可用的完整验证属于 D14。前提验证通过不能记为完整功能验收通过。

发布验收需记录：真实 BSSID 变化且无线调试被关闭后的恢复；亮屏连续操作至少 60 分钟；断网、休眠、旋转及剪贴板大消息期间不粘键、不误接管；USB 原有行为不退化；PC/Android 重启和 PC 地址改变给出准确恢复提示；并验证错误 pin/token、旧 sessionId、重复连接、owner 竞态和部分部署失败。

在局域网恢复且无策略阻隔时，目标为 10 秒内重新达到已就绪；断线后本机接管释放及 Android 按键释放目标不超过 2.5 秒。每项记录实际测量值、设备/系统、复现步骤与日志；未实际发生的漫游不能用手动断 socket 替代验收。

截至本文：已有本机 C#/Java TLS 互通、daemon 模型、bootstrap 参数与旧回归测试的探索报告；尚无脱离 ADB、目标真机 TLS、AP 漫游、完整 UI 和端到端验证。参数组合断言数量不是场景覆盖数量。现有代码与本文 v2、owner 锁、可选剪贴板及就绪语义存在差距，全部需要按实施计划复核。
